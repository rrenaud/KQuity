1 · Data

For each game in the quality-filtered set we walk the playerKill events and keep (killer_x, killer_y, killer_pid, killed_pid, killed_category) plus the game’s map index, quality rank, and gold_on_left flag. Positions are mirrored to a canonical gold-on-left frame; y is flipped from Cartesian (game) to pixel coordinates so it matches the screenshot.

Every quality-filtered game is included — 182,447 games in total (49,147 day, 50,943 night, 47,427 dusk, 34,891 twilight), 6,096,016 kill events, 650,988 of them queen deaths. Where applicable, both sides of a map are mirror-folded onto the gold half via x' = min(x, 1920 - x), doubling effective sample density in the visible area.

2 · Density estimation: why diffusion

For a 2D point set on a 1920×1080 canvas the standard estimator is a Gaussian kernel density. With the bandwidths that surface map-feature structure (~24 px) a Gaussian KDE has a problem specific to this domain: it spreads density isotropically, including across solid map geometry. A queen kill near a platform edge contributes weight to cells inside the stone below it, and a kill in one chamber spills across thin walls into adjacent chambers.

Three estimators were compared:

  1. Naive Gaussian KDE. density = gaussian(H, σ). Closed-form, fast, ignores geometry.
  2. Mask-renormalized Gaussian. Build a binary mask M of cells where any kill ever landed (an empirical playable region; no manual segmentation). Compute num = gaussian(H·M, σ) and den = gaussian(M, σ), then density = num / den on M. Corrects the boundary dilution that pulls naive density down near edges, but the kernel still reaches across thin walls.
  3. Wall-respecting diffusion. Iterate f ← (1 - α)·f + α·mean(playable neighbours of f) with α=0.2. Cells outside M are treated as no-flux boundaries, so density never crosses solid geometry. Variance after T iterations is approximately σ² ≈ α·T cells² per axis, so the iteration count is set to match a 24-px target bandwidth.

The trade-off:

  • Cost. Naive: one gaussian_filter call. Mask-renormalized: two. Diffusion: O(σ²/α) ≈ 180 sparse stencil applications.
  • Mask quality. Mask-renormalized and diffusion both require a binary mask. Using empirical kill positions to define it avoids a manual map-geometry segmentation but introduces a small data dependency: regions that are playable but rarely visited get underrepresented in the mask. The mask is built from the smoothed histogram of all kills (not just queen deaths), which keeps the mask stable.
  • Sharpness vs. bias. Diffusion has the lowest cross-wall bleed and is the choice used everywhere else in this report. Mask-renormalized sits between naive and diffusion in both cost and sharpness; useful as a quick-look estimator.

All overlays use a power-curve alpha, alpha = 0.92 · progress^0.55 with progress = norm(density) clipped to [0,1] and zero where the cell density is zero, so low-density cells let the underlying map sprite show through and high-density cells render opaque.

5 · Bucketed animations

Each game is assigned a per-game scalar attribute and the night-map sample is partitioned into 12 equal-mass buckets by quantile. The densities from §3 are recomputed for each bucket and rendered as one frame, producing a 12-frame mp4 per plot type. Frame interval 0.5 s.

5.1 · By game quality

Bucket attribute: the game’s quality-classifier rank in quality_filtered/encoded/all_games.bin (the bin is sorted by quality_score descending, so each game has a unique rank). Bucket label gives the percentile range; bucket 0–8% is the highest-quality games. Each bucket holds ~4,245 night games.

5.2 · By queen skill

Bucket attribute: the average pre-game OpenSkill PlackettLuce μ of the two queens in the game. Ratings come from compute_ratings.py, which walks unfiltered_partitioned/usergame.csv chronologically and records the pre-game per-position μ snapshot before each game updates the model. Games with no rating record are dropped, leaving 30,222 night games. Each bucket holds ~2,518 games.
